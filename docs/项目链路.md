# 项目链路（架构与数据流总览）

> 本文件描述 `playerallocationsystem_next`（线上 `dota.playerallocationsystem.online`）的端到端链路。
> 日常改动以 `README.md` 为准，本文档负责把「一条请求从浏览器到数据库再回来」的每一段讲清楚。
> 最后更新：2026-10-23。

---

## 0. 一句话拓扑

```
浏览器 / 微信内置浏览器
        │  HTTPS (443)
        ▼
   Nginx（反代 + HTTPS 终止 + 安全头 + /stats auth_basic）
        │  http://127.0.0.1:3000
        ▼
   PM2 单实例  laroja-site  ──  Next.js 16（Pages Router）──  React 18
        │  pg 连接池（DATABASE_SSL=off，同机 PostgreSQL）
        ▼
   本机 PostgreSQL  （26 张表，库名 laroja）
```

- 服务器：`root@YOUR_SERVER_IP`（阿里云 ECS，**2 核 / 1.7G 内存**），项目目录 `/www/wwwroot/laroja`。
- PM2 应用名 `laroja-site`，**`instances: 1` fork 模式**（限流/缓存全是单进程内存实现，多实例会各算各的）。`max_memory_restart: 450M`，避免和 PostgreSQL 抢内存被 OOM Killer 干掉。
- 技术栈：**Next.js 16.3.0（Pages Router / Turbopack）+ React 18.2.0 + pg + SheetJS**。**没有 TypeScript、没有 Tailwind，没有组件库。**

## 1. 请求链路（一次页面访问怎么走）

1. 浏览器请求 `https://dota.playerallocationsystem.online/food`。
2. Nginx（443）终止 TLS，反代到 `127.0.0.1:3000`。
3. `next-server` 渲染 `/food`：
   - 服务端 `getServerSideProps` 通过 `lib/db.js` 的 `pool` 查 `foods` / `food_reviews` 等。
   - 返回 HTML，其中 `<link>` / `<script>` 引用 `/_next/static/chunks/*`（Turbopack 命名，**不是 `/css/`**）。
4. 浏览器加载静态资源 → 执行 React → 水合（hydration）→ 页面可交互。
5. 客户端再按需调 `/api/*`（列表、报名、AI 分析等）。

**关键事实**：静态资源由 `next-server` 直接从 `.next/static` 发，Nginx 只是反代。所以 `.next` 目录被中途改写时，旧 HTML 引用的旧 hash chunk 会 404，React 起不来 → 「页面看得见但按键按不动」。这就是 2026-10-23 #425 故障的现场（见第 5 节部署链路）。

## 2. 鉴权链路

登录账号体系与「公开名片」是**两套字段**，这是本项目最容易踩的坑：

| 概念 | 存哪 | 含义 |
|---|---|---|
| 登录账号 | `play_score.name`（主键） | 用来登录的 ID，改名要迁移历史表 |
| 群昵称（公开名片） | `players.nickname` | 群里显示的昵称，改它**不影响登录** |

**注册**（`/api/register`，唯一建号入口）：
- `username → play_score.name`，`group_nickname → players.nickname`。
- 查重不区分大小写（`LOWER(name)=LOWER($1)`），否则 `DOM` 能拿到 `dom` 权限。

**登录**（`/api/login`，只校验不建号）：
- 账号不存在返回 `401 USER_NOT_FOUND`，**绝不自动建号**（防撞库 / 防误建）。

**会话**：
- `lib/auth.js` 用 HMAC 签名 httpOnly cookie `dd_session`，30 天有效。
- `AUTH_SECRET` 未配则回退 `sha256(DATABASE_URL)`，**改它全体掉线**。

**四档守卫**（按破坏性选档）：

| 守卫 | 拦住谁 | 典型用途 |
|---|---|---|
| 无 | — | 公开读：赛事、群友、美食、开黑列表、图片 |
| `denyIfNotLoggedIn` | 匿名 | 报名、发开黑卡、AI 分析、改自己资料 |
| `denyIfNotAdmin` | 非管理员 | 选手增删改、赛事 CRUD、赛程、选队长 |
| `denyIfImportNotAdmin` | 非管理员（带 `x-excel-import:1`） | 整包 Excel 导入 |
| `isAdmin`（页面级） | 非管理员 | `/admin/*`、`/main` 的 `getServerSideProps` |

**前端登录态**：`hooks/useSession.js` 统一监听 `dd:session-changed` 窗口事件；`Layout` 在 `pathname` 变化时 `refresh()`。**没有 React Context**，别用 `localStorage.user` 判登录。

**限流**：登录失败按 `ip:` + `user:` 双维度计数，10 分钟 5 次锁定。

**改用户名**（`/api/admin/rename-account`，后台「重置密码」旁边）：
- 主键 `play_score.name` 更新，并把四张按账号名存历史数据的表（`page_views` / `party_posts` / `party_signups` / `support_reports` 的 `account_name`）一起迁移，每张表单独 `SAVEPOINT` 防止老库缺表拖垮整次改名。
- 两个禁区：**不能把任何人改成 `ADMIN_NAMES` 里的名字**（凭空发管理员权限）；**管理员账号本身不许改名**。

**安全债**：密码是单次 `salt:sha256(salt+pwd)`，无迭代。升级用 scrypt 但要保持旧格式兼容。

## 3. 数据模型链路（26 张表）

> 线上真实行数见括号。与旧 README「16 张表」已不符，这是核对后的最新清单（2026-10-23）。

**账号与选手（身份层）**
- `play_score`（69）— 登录账号，密码 `salt:sha256`，`previous_name` / `name_changed_at` / `name_changed_by` 审计列
- `players`（169）— 选手全局资料（昵称、SteamID、天梯分、英雄池、默契队友、仇人）
- `player_aliases`（27）— 别名 / 曾用名
- `player_group_nicknames`（94）— 群昵称历史快照
- `player_steam_accounts`（106）— Steam 账号绑定（一个选手可绑多个）
- `user_configs`（0）— 用户级配置（暂未使用）

**赛事层**
- `tournaments`（11）— 赛事主体，7 态状态机（planning / ongoing / elimination / semifinal / final / finished / postponed），**由管理员手动切换**
- `tournament_players`（364）— **赛事内快照**：同一选手在不同赛事可有不同分数/位置/英雄，`is_captain` 也限定在赛事内
- `tournament_rounds`（9）— 轮次 / 阶段
- `tournament_teams`（1）— 赛事 ↔ 队伍关联
- `tournament_placements`（31）— 名次
- `matches`（43）— 对阵与比分
- `player_tournament_participations`（379）— 参赛记录
- `dota_matches`（43）— 从 OpenDota 抓取的对局
- `dota_match_players`（430）— 对局选手明细

**队伍层**
- `teams`（80）— 队伍，`captain_id` 指向队长
- `team_players`（392）— 队员关系，带队内担任位置

**社区内容层**
- `party_posts`（2）/ `party_signups`（0）— 开黑卡片与报名
- `foods`（106）/ `food_reviews`（36）— 美食与饭后评价
- `messages`（5）— 留言板
- `page_views`（7406）— 浏览记录（按 `account_name` 存，改名要迁移）

**运维层**
- `support_reports`（412）— 反馈与前端自动报错工单（按 `account_name` 存，改名要迁移）

**核心链路图**：

```
play_score ──1:1── players
                    │
                    ├── player_aliases / player_group_nicknames / player_steam_accounts   (1:N 身份维度)
                    │
                    ├── 报名 ──▶ tournament_players ──▶ tournaments
                    │                  │
                    ├── 参赛 ──▶ player_tournament_participations ──▶ tournaments
                    │
                    └── team_players ──▶ teams

tournaments ── tournament_teams ──▶ teams
tournament_rounds ──▶ matches ──▶ dota_matches ──▶ dota_match_players
tournament_placements ──▶ tournaments   (名次)
```

> `players` 存的是「默认资料」，报名时复制成 `tournament_players` 快照。之后改全局资料不影响已报名的赛事 —— 这是刻意设计。

**分层（用户裁定方案 A）**：只锁破坏性操作，日常操作登录即可。

**列漂移注意**：`players.created_at` 是 varchar 只到天，必须 `ORDER BY p.id DESC`（雪花 id 单调）；`id` 一律按字符串传（超 `MAX_SAFE_INTEGER`）。读表一律 `SELECT *`，写更新按行里实际存在的键动态拼 `SET`（`db.js` 建表写了部分列，线上老库没有，全列 UPDATE 会 500）。

## 4. 时区与解析层（容易出 bug 的三条铁律）

1. `datetime-local` 串服务端 `new Date()` 解析不了 → 浏览器转 `toISOString()` + `tz_offset`（+08 = -480，见 `parseClientInstant`）。
2. `timestamp without time zone` 传给 +08 node 少 8 小时 → 展示 `col AT TIME ZONE current_setting('TimeZone')`；`tournaments.start_date/end_date` 例外（纯日期 `dateOnly()`）。
3. 本地 +08，**时区 bug 本地复现不出来**，排查必须 `TZ=UTC node ... next start`。

**地区**：`players.region` 是空格分隔定长路径 `国 省 市 区`，`lib/regions.js` 是唯一解析层（不 import 数据）；数据不进 bundle（按需 `fetch` `public/data/china-division.json` + `countries.json`，有文本兜底）。

## 5. 部署链路（2026-10-23 重构后）

> 这是 #425 故障的根治点。旧流程在服务器原地 `next build`，把访问中的用户挂在半路上。

**为什么不能服务器构建**：线上只有 2 核 / 1.7G，服务器 `next build` 要跑 **5.4 分钟**（本地 13 秒）。那 5.4 分钟 next-server 抢不到 CPU，Nginx 等上游超时 → 504；用户等不及主动断开 → 499。一次部署实测 28×504 + 137×499。

**现在的流程（`deploy/deploy.sh`）**：

```
本地：
  [1/5] npm run build（prebuild 语法补丁 → next build → postbuild 浏览器语法检查）
        ↑ 这一步不仅校验，还顺带产出上线产物 .next（原来构建完就扔）
  [2/5] 打 2.8M 产物包（排除 .next/cache —— 38M 的 build 缓存 next start 根本不用）
  [3/5] scp 上传到服务器 /tmp

服务器：
  [4/5] 解压
        → 修 .next/node_modules 的 Turbopack 符号链接（见下方「坑」），逐个校验
        → 合并上一版独有的 static chunk（cp -an，保留 14 天）—— 开着旧页面的用户不会 404
        → 原子 mv（.next → .next-prev，.next-build → .next，再删 .next-prev）
  [5/5] pm2 restart
        构建失败：完全不动线上产物，站点继续用旧版跑
回滚：./deploy/rollback.sh  秒级切回上一版快照（含构建产物）
```

**Turbopack 符号链接坑（重要）**：Turbopack 把 `pg` / `xlsx` / `nodemailer` 这类外部包写成 `<包名>-<哈希>` 虚拟名（如 `pg-587764f78a6c7a9c`），并在 `.next/node_modules/` 放一个**指向构建机绝对路径的符号链接**：

```
pg-587764f78a6c7a9c -> /e/lzf/.../node_modules/pg   ← 在 Windows 上构建
```

传到 Linux 就是死链：**页面全 200、静态资源全 200，但所有 API 500**（`Cannot find module 'pg-…'`）。部署脚本解压后统一改写成 `../../node_modules/<包名>` 指回服务器自己的依赖，并**逐个校验 `package.json` 真能读到**，任一失败就中止、不动线上。

**本地/服务器构建切换**：`distDir = process.env.NEXT_DIST_DIR || '.next'`，构建到 `.next-build` 再原子切换。`--server-build` 参数保留作为回退（改了原生依赖、产物跨平台跑不起来时用）。

**实测对比（同一站点，2026-10-23 三次部署窗口）**：

| 指标 | 原地构建 | 独立目录 + 服务器构建 | 本地产物上传（现状） |
|---|---|---|---|
| 部署耗时 | 40~90s | 8 分钟 | **25 秒** |
| 5xx | 11×500 + 4×502 | 28×504 | **0** |
| 499 | 7 | 137 | **0** |
| chunk 404 | 16 | 0 | **0** |

**静态资源保留 14 天**：旧 chunk 合并进新产物，大多数情况下用户手里的旧页面根本不会再 404，连自愈都不用触发。

## 6. 客户端自愈链路（防「按键失灵」）

自愈脚本内联在 `pages/_document.js`，是「页面看得见但按不动」的最后兜底。

**触发条件**：
- 静态资源 404：`window.addEventListener('error')` 捕获 `<script>` / `<link>` 的加载错误，且 URL 含 `/_next/static/`。
- 水合超时：首屏探针 6 秒后发现 `#__next` 上没有 `__react*`，判定水合失败。

**动作 `heal(reason)`**：
- `location.replace(pathname + '?_r=' + Date.now())` —— **必须换新 URL 不能只 `reload()`**：PC 微信（Chrome 144 / XWEB 25799）HTML 缓存极激进，普通 reload 会拿回同一份旧页面（旧 HTML 引用旧 chunk → 又 404 又 reload → 死循环，这正是 #425 现场）。
- 拼新 URL 前先剥掉已有的 `_r`，否则每次自愈累加 `?_r=a&_r=b`。

**配额（防无限刷新）**：
- 计数存 `sessionStorage['laroja-selfheal']`，一个会话最多 2 次。
- 时间戳存 `sessionStorage['laroja-selfheal-at']`，两次自愈间隔 ≥ 3 秒（一个页面通常并发加载七八个 chunk，不隔开会在几十毫秒内把 2 次配额烧光）。
- ⚠ 时间戳**不能放内存变量**：`heal()` 会 `location.replace` 跳走，新文档重跑 IIFE，内存变量归零 → 间隔判断失效（实测 81ms 内连跳两次）。

**善后**：水合成功后 `history.replaceState` 把地址栏的 `_r=` 抹掉（它只是缓存清除器，页面正常后不该留在 URL 里）。

## 7. 浏览器兼容底线

真实用户下限：**iOS 16.0 / 16.2 Safari，微信内置 Chrome 86（XWEB 4433）**。也就是**上限 = Safari 16.3 / Chrome 86**。

**根因**：Next 16.3.0 的 `next/dist/shared/lib/router/router.js` 用了 ES2022 **class 静态块** `static{ this.events = mitt() }`（需 Chrome 94+ / Safari 16.4+）→ 老引擎整包 `Unexpected token '{'` → React 从未启动 → 「JS 全 200 却一次 `/api/*` 都没发」。桌面 Chrome 与新 iPhone 完全看不出来。

**两步防护（缺一不可）**：
1. `prebuild` 跑 `scripts/patch-next-syntax.cjs`：`static{ this.X = e; }` → `static X = e;`（改 43 处，幂等）。
2. `postbuild`（build 末尾）跑 `scripts/check-browser-syntax.cjs`：产物里还有静态块 / 后行断言就**构建失败**。

**运行时垫片**：`_document.js` 内联探针（`Object.hasOwn` / `Array.at` / `String.at` / `TypedArray.at` / `structuredClone`）；老引擎启动成功上报 `category=boot-ok`，区分「没报错」与「没人访问」。

**AI 服务**：服务器 `.env.local` 配了 DeepSeek（`ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic`），**必须显式 `thinking:{type:'disabled'}`**，否则 reasoning 块挤空正文。
